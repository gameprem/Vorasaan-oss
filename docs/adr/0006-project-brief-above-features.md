# A Project Brief sits above Features

Specs describe one Feature; nothing described the Project as a whole, so the AI drafted Choices and Specs without knowing the business goals, what the product already does, or what the company expects of a new Feature. We add a versioned, human-approved **Project Brief** (Markdown, like the Spec in ADR 0002), built by **Grilling** the people in the Project and, for an existing codebase, from Project Attachments and an opt-in **Repo Scan** summary sent by the CLI (never whole source files). **Feature Guidelines** are set as an Organization default that each Project can override. The Brief and the Guidelines become context for every AI workflow, and power **Feature Suggestions** that a PO accepts or dismisses. The alternative, a free-text Project description, was rejected: it would not be versioned or approved, so the AI's context could drift without anyone signing off.
