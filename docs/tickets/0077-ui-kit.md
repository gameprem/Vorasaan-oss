# 0077: UI kit, and replace browser-native controls

## Goal
Every form in the web app uses our own accessible, themed controls instead of browser-native ones, with searchable pickers and Thai-aware dates (ADR 0016).

## Scope
- **The kit**, in `apps/web/components/ui/`, on `react-aria-components`, styled with the ADR 0008 tokens in light and dark:
  - **Select** and a searchable **ComboBox**, with an optional icon and description per item. Used for the model, Team Role, person and Feature pickers.
  - **Person picker:** a ComboBox showing each person's avatar and Team Roles.
  - **Time-zone combobox:** searchable by city or zone in English and Thai ("Bangkok" and "กรุงเทพ" both find `Asia/Bangkok`), showing the current offset.
  - **Date and time picker**, with an optional Buddhist-era display (2569 for 2026) that follows the person's language. Used by Delegation periods, public holidays, Quiet Hours, Working Time and the Decision Lead Time range.
  - Checkbox, Radio group, Switch, Segmented control, Menu, Popover, Tooltip, Toast, Tabs, Dialog, Skeleton and Empty state.
- **Gallery:** a dev-only page at `/dev/ui` showing every component in every state, in both themes. It is not served in production.
- **Replace native controls app-wide:** every native `<select>` (about 22 today, in about 15 files) and every native checkbox, radio, date and time input (about 22). Behaviour stays the same; only the control changes.
- **Existing look:** pills, tone-separated surfaces, no hard borders (ADR 0008).

## Acceptance criteria (test first)
- [x] A test greps `apps/web` (outside `components/ui/`) and fails on a native `<select>`, or an `<input>` of type date, time, datetime-local, checkbox or radio.
- [x] Unit tests: the time-zone combobox finds `Asia/Bangkok` from "Bangkok" and "กรุงเทพ"; the date picker shows a Buddhist-era year when asked and stores the same ISO date either way.
- [x] e2e on `/dev/ui` and the key forms (Delegation, Settings → AI models, Settings → Working Time, raise a Decision Request): every control works with the keyboard alone, and axe reports no violations, in light and dark.
- [x] A screen reader announces a ComboBox's options and the selected date (checked with axe and the accessibility tree in e2e).
- [x] All existing e2e tests still pass.

## Decisions
- **Kit layout.** One small file per component in `apps/web/components/ui/` (`select`, `combo-box`, `person-picker`, `time-zone-combo-box`, `date-picker` with `DatePicker`/`DateRangePicker`/`TimeField`, `checkbox`, `radio-group`, `switch`, `segmented-control`, `menu`, `popover`, `tooltip`, `toast`, `tabs`, `dialog`, `skeleton`, `empty-state`, `button`), plus shared pieces: `field.tsx` (label, hint, error, the tonal "well", `useFieldValue`), `options.tsx` (the `Option` row: icon, label, description, sections), `date-values.ts` (string ⇄ date conversions) and `provider.tsx` (the locale and the toast region, once in the root layout). The class-name strings in `components/ui.ts` stay for plain inputs and buttons.
- **One prop vocabulary.** Every field takes `label` (or `aria-label`), `description`, `name`, `value`/`defaultValue`/`onChange`, `isRequired`, `isDisabled`, `className`, `labelClassName`. Values are the strings native controls used: Select and ComboBox values are ids where `''` may be an Option ("Default", "The Organization's"); dates are `2026-03-05`, day and time `2026-03-05T09:30` (the `datetime-local` format), times `09:30`. Checkbox, Switch and RadioGroup keep React Aria's `isSelected`/`value` naming.
- **Forms keep working.** A field with `name` renders its own hidden input, so FormData and server actions get the same value as before (`''` included, which React Aria keys can't be). Validation stays native (`validationBehavior="native"`), so `required` still blocks a submit.
- **Two React Aria behaviours we turned off.** React 19 resets a `<form action>` after the action and React Aria listens for that reset: controlled kit fields ignore it, as a controlled native input does (otherwise ticking "Hold cards during quiet hours" and saving unticked it). And a field never calls `onChange` with the value it already has (a refresh re-reporting it cleared "Saved").
- **Time zones** (`lib/time-zones.ts`): each zone is its IANA id with its city, its current offset ("UTC+07:00") and a small alias table (Thai names, countries, big cities: "กรุงเทพ", "ไทย", "Saigon"…). The search matches every typed word against all of them; the input shows the id, as before.
- **Dates:** the kit's locale follows the person's language (`en-GB`, a 24-hour clock and day/month/year; `th-TH`). `buddhistEra` shows 2569 for 2026 (`-u-ca-buddhist`); unset, Thai shows it and English doesn't. The stored value is always converted back to the ISO (Gregorian) date. Delegation periods use the day-and-time picker; holidays a day; Quiet Hours and Working Time a TimeField.
- **What replaced what.** ComboBox for the Project-or-Feature picker (with sections), person pickers (Delegator, Delegate, New Decider, adding a Team member, the dev identity switcher) and time zones; Select for models, providers, Team Roles, languages, units, Teams, access, kinds and Redraft pointers; RadioGroup (tiles or dots) for the request kind, Choices, recipients, provider kinds and Guideline modes; Checkbox (plain or chip) everywhere else. Choice tiles in the decide form are `Radio variant="bare"` with their old look.
- **Gallery** at `/dev/ui`: every component and state, a theme switch (`?theme=light|dark`) and a form that shows its submitted FormData. Served when `NODE_ENV` isn't production or `VORASAAN_DEV_AUTH=true` (`devPages()` in `lib/api.ts`), the same flag as the identity switcher; otherwise a 404.
- **Global CSS clashes.** The shell's `.group` and `.dot` classes in `globals.css` would restyle Tailwind's `group` marker and a radio's dot, so the kit uses the named group `group/kit` and `radio-dot`. Unlayered `:focus-visible` outlines beat Tailwind utilities, so parts whose focus shows as a fill or ring carry `kit-quiet-focus`. Placeholder and section text use `fg-soft`, since `fg-faint` fails AA contrast.
- **Bundle** (first-load client JS per route, gzip, from the `next build` client reference manifests; before → after): every page +2.8 kB (the locale provider; the toast region and the dev switcher's picker load lazily). Pages with pickers: `/settings/ai` 249.9 → 329.1 kB (+79), `/settings/members` 244.3 → 318.4 (+74), `/settings/organization` 244.2 → 318.2 (+74), `/features/[id]/raise` 243.4 → 272.6 (+29), `/conversations/new` 301.1 → 381.1 (+80), `/projects/[id]` 297.3 → 375.3 (+78), `/features/[id]` 291.1 → 367.1 (+76), `/requests/[id]` 250.9 → 340.8 (+90); with a date or time picker: `/settings/delegations` 245.7 → 379.8 (+134), `/settings/response-windows` 245.7 → 383.6 (+138), `/settings/notifications` 246.2 → 384.1 (+138), `/teams/[id]` 246.4 → 383.1 (+137), `/setup` 248.2 → 388.7 (+141). `/conversations/[id]` stays at +2.8 kB: the Redraft Selects there load on demand (`LazySelect`). This is the cost ADR 0016 accepted.
- **Tests.** `components/no-native-controls.test.ts` greps `apps/web` (outside `components/ui/`) for `<select` and checkbox, radio, date, time and datetime-local inputs. `components/ui/time-zone-combo-box.test.ts` (Bangkok and กรุงเทพ find Asia/Bangkok; ids, cities with spaces, offsets) and `components/ui/date-picker.test.tsx` (server-rendered: 2569 shown with `buddhistEra` and for Thai, 2026 otherwise, the same ISO date submitted, day and time kept). e2e: `ui-kit.e2e.ts` (axe on `/dev/ui` in light and dark, with a Select, a ComboBox and a calendar open; the whole gallery form filled by keyboard and its FormData checked; the ComboBox's options and active option via `aria-activedescendant`, and the date segments' values and the "Selected Date" description), `ui-kit-forms.e2e.ts` (Delegations, AI models, Response Windows, raising a Decision Request and inviting, by keyboard and axe-clean in light and dark) and axe on the setup wizard's calendar step. Existing specs now drive the kit through `e2e/kit.ts` (`chooseOption`, `searchAndChoose`, `fillTime`, `tick`…); a few wait for Settings to hydrate before pressing keys, since the bigger pages hydrate later.
- **App-wide contrast (follow-up).** `fg-faint` (3.14:1 on white) is for large text, disabled states and decorative marks only; small text uses `fg-soft`. The Sidebar's faint labels (the Thai name, `kbd`, `.side-empty`, `.muted`, the role under your name, the Project caret) moved to `fg-soft`, light `--saffron` darkened to `#955800` (the Inbox count was 3.62:1 on its wash) and `--jade` to `#0a775c`. axe now checks the whole page, Sidebar included: `a11y-pages.e2e.ts` runs every page and tab in light and dark, and `shell.e2e.ts` the Sidebar expanded, collapsed and as a drawer.
- **Left open.** No form uses the DateRangePicker yet (the Decision Lead Time panel has no range control); it is in the gallery for when it does. The Settings modal still uses its own dialog code, not the kit's Dialog. Picker pages carry 75–140 kB more; loading popover contents on demand could trim it later.
