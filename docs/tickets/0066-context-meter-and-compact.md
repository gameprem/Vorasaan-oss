# 0066: Context meter, /compact, chat history and cursor pagination

## Goal
A person sees how full their Conversation is, and can compact it themselves with a say in what the Conversation Summary keeps (ADR 0012). The whole chat history stays readable, and long Conversations open fast and load older messages as you scroll up, like a chat app.

## Scope
- **Usage from the server:** the server already plans and counts each turn (0060). It now sends the numbers:
  - a `conversation.usage` event on the event stream after each turn, and the same object in the turn's response;
  - the shares of the plan (foundation and system prompt, retrieved context, history, room for the reply), the model's Context Window, the history used against its share, the compaction threshold, and the last turn's cache reads (0061);
  - a Zod contract in `@vorasaan/shared`.
- **Meter:** a small meter under the composer, next to the model picker.
  - It shows how full the history share is, and turns a warning colour near the compaction threshold.
  - Hover or tap shows the shares, the Context Window and the last turn's cache reads.
  - Switching model in the picker recomputes it for that model's window.
  - Light and dark tokens (ADR 0008), and an `aria-label` that reads the numbers.
- **Manual compaction:**
  - A "Compact now" action in the meter's popover, and a `/compact [focus]` command in the composer.
  - The focus text steers the summary (for example "keep the payment limits"), and is stored with the compaction.
  - Before folding, if something agreed in the chat isn't recorded in the Spec or the Brief yet, the AI offers an Action Card to record it. Compaction goes on once the person acts on it or skips it. This closes what 0060 left open.
- **Chat history shown normally:** older messages are no longer folded behind a button or dimmed; this replaces the 0060 "Earlier messages were summarized" fold. Where a compaction happened, a thin divider reads "↑ The AI reads the messages above as a summary · View summary". A Conversation compacted several times shows one divider per compaction.
- **Reading the summary:** "View summary" on a divider shows the Conversation Summary's sections as of that compaction. Whether a person may edit it is decided here and recorded; if editable, the edit is written to the Conversation's history.
- **Cursor pagination**, like a chat app:
  - Opening a Conversation loads the latest ~50 messages, scrolled to the bottom.
  - Scrolling near the top loads older pages from `GET /conversations/:id/messages?before=<cursor>&limit=50`. The cursor is stable on `(createdAt, id)`, so messages with the same timestamp are never skipped or repeated.
  - The scroll position is kept when a page loads; the view doesn't jump. A skeleton shows while loading (0077).
  - When new messages arrive over SSE while the person is scrolled up, a "↓ New messages" pill appears; it scrolls to the bottom.
  - A deep link to a message loads the page around it, and pages load both ways from there (`after=<cursor>` too).
  - Pagination is independent of compaction and token budgets: it only decides what the screen loads, never what the AI reads.

## Acceptance criteria (test first, real Postgres + `FakeAiPort`)
- [x] The usage numbers of a turn match the server's budget plan for that model's window.
- [x] Switching to a model with a smaller window returns usage for that window.
- [x] `/compact keep the limits` folds the history, passes the focus to the summarizer, and stores it.
- [x] Compacting with an agreed point that isn't in the Spec offers an Action Card first.
- [x] API: pages come newest first by `(createdAt, id)`; the first and last pages have the right edges (no cursor past the end, no duplicates); messages with the same `createdAt` are neither skipped nor repeated.
- [x] API: messages that arrive while a person pages back don't shift or repeat the older pages; a deep-link page around a message pages both ways.
- [x] Someone who can't read the Conversation gets a 404 on its messages.
- [x] Browser-verified: the meter updates live after each turn and warns near the threshold, `/compact` compacts the chat, and "View summary" shows the summary.
- [x] e2e with a 300-message Conversation: it opens at the bottom with the latest page; scrolling up loads more without the view jumping; a divider shows after compaction; messages above it are still readable, not folded or dimmed; a message arriving while scrolled up shows the "↓ New messages" pill.

## Decisions
- **Schema** (migration `20261003140000_conversation_compactions`): a `ConversationCompaction` row per fold: `number` (1, 2, 3… per Conversation), `trigger` (`AUTO`, `MANUAL`, `TOO_LONG`), `focus`, `summarizedThrough`, the `summary` as that fold left it, and `createdById` for a fold by hand. Conversations compacted before this ticket get one `AUTO` row from their current summary. `Conversation.lastInputTokens` and `lastCacheReadTokens` hold the last reply's provider usage, summed over its steps. Every fold (automatic, too long, by hand) goes through one `saveFold`, which writes the summary and the row in one transaction and sends `conversation.compacted`.
- **API contract** (`@vorasaan/shared` `conversation.ts`):
  - `ConversationMessageView.position`: the Conversation's own write order.
  - `GET /conversations/:id` takes `?around=<messageId>&limit=` and returns the latest page (50) or the page around a message, with `page: { olderCursor, newerCursor }` and every compaction (`compactions[]`, `ConversationCompactionView`: number, trigger, focus, `summarizedThrough`, `beforeMessageId`, `createdBy`, `createdAt`). Starting a Conversation returns the same shape.
  - `GET /conversations/:id/messages?before=|after=<cursor>|around=<messageId>&limit=` (1 to 100, default 50; more than one direction is a 400) returns `ConversationMessagePage` `{ messages (oldest first), olderCursor, newerCursor }`. A cursor is null when there is nothing more that way, so no cursor points past the first or the latest message.
  - `GET /conversations/:id/usage?approvedModelId=` returns `ConversationUsage`; the turn's answer carries it too (`ConversationTurnView.usage`, null in a Grilling Conversation), and so does the SSE event `conversation.usage` `{ conversationId, usage }`, after each turn and each fold by hand.
  - `POST /conversations/:id/compact` `{ focus? (up to 500 chars), skipRecordCheck? }` returns `CompactConversationResult`: `COMPACTED { conversation, compaction, usage }` or `RECORD_FIRST { unrecorded, messages, card }`. 409 when only the latest turn follows the summary; 422 in a Grilling Conversation; 404 for anyone but the owner.
  - `GET /conversations/:id/compactions/:compactionId` returns `ConversationCompactionSummary`: the Markdown, its sections, and whether it is the summary the AI reads now.
- **The cursor is on `position`, not `(createdAt, id)`.** A cursor names one message (`base64url("<position>.<id>")`), checked against the Conversation: another Conversation's cursor is a 400, another Conversation's message for `around` a 404. `position` is unique per Conversation, already indexed with it, and is the order the chat was written in. Equal `createdAt`s happen (messages written in one transaction share a timestamp), and ordering those by a random uuid would show them out of order; by position they are never skipped, repeated or swapped. The web merges pages and live messages by `position` as well.
- **The usage numbers are the turn's own plan.** `plan` is `planBudget` of the model's window through the same `ContextBudgets.forTask('chat', …)` call a turn makes (system prompt, tools, slack); `history.share` is its history share, `compactAt` 70% of it and `warnAt` 60% (`BUDGET_CONFIG.compaction.warn`, used only by the meter); `used` is the Conversation Summary plus the messages after it. After a turn, `used` is the estimate scaled by that turn's own count (0060 counts once per turn, so there is no second count); `GET …/usage` and a fold by hand count once on the model. For a model picked but not sent with yet, `?approvedModelId=` answers for its window and changes nothing (422 unless it is an Approved Model).
- **Cache reads** come from the provider: `ChatChunk` has a last `{ type: 'usage', usage: { inputTokens, cacheReadTokens } }`, from the AI SDK usage (0061's `cacheUsageOf`), sent only when the provider reported something. `FakeAiPort` reports its own count of the prompt and `cacheReadTokens` (0 unless a test sets it).
- **Compaction by hand** folds everything before the last turn (the person's last message and what followed stay word for word), even under the threshold. The focus goes to the summarizer (a fenced `<focus>` section in `summarize-conversation.md`: keep everything about it in full) and is stored with the compaction.
- **Record before folding** (closes what 0060 left open, for compaction by hand). The summarizer now also gets the current Spec (Feature Conversation) or Project Brief and returns `unrecorded`: the agreed points it doesn't record yet (`ConversationFoldDraft`; empty when it gets neither). When some are missing, nothing is folded. The server stores an assistant message that lists them, with a `draftSpecProposal` or `draftBriefProposal` call whose proposal is the current document plus an "Agreed in a Conversation" section, and runs it through `ActionCardsService.run` like any tool call, so the card, its TOOL result and the events are the usual ones. The person approves or declines the card (or asks for a Redraft, 0065, to work the points in where they belong), or skips it; the web then compacts again with `skipRecordCheck`. Someone who may not propose a change there gets no card (the message is removed) and the fold goes on. Automatic compaction, which runs before a reply, doesn't stop for this: as in 0060, its summary says what isn't recorded, and the AI may offer a card on a later turn.
- **The summary is read-only.** "View summary" shows it; nobody edits it. It is the AI's working notes of messages that stay in the Conversation, while the Spec, the Decision Log and the Brief are the source of truth (ADR 0001). An edited summary would silently disagree with the messages above the divider and would need its own history. Instead, a person steers it with `/compact <focus>` and records what matters through the Action Card above. Each compaction keeps its own summary, so an older divider shows the summary as it was then ("a later compaction replaced it").
- **Web** (`components/chat/`):
  - `context-meter.tsx`: a ring and a percentage next to the model picker (jade; saffron from `warnAt`; lacquer from `compactAt`), with an `aria-label` that reads the numbers out. Hovering shows the shares, the Context Window and the last turn's cache reads. Pressing opens the kit popover with the same numbers and "Compact now". The hover uses React Aria's Tooltip with the kit's surface (`tooltipClass`, now exported): the kit `Tooltip` wraps plain elements, and the meter's trigger is itself a React Aria Button inside a `DialogTrigger`. The meter loads from `GET …/usage` for the model the next reply runs on, again when another model is picked, and then follows each turn's `usage` and `conversation.usage`.
  - `/compact [focus]` typed in the composer compacts instead of sending; a toast says when it's done. On `RECORD_FIRST` the card appears under the AI's message and a bar above the composer says compaction is waiting for it, with "Skip and compact". Approving or declining the card compacts.
  - `compaction-divider.tsx`: "↑ The AI reads the messages above as a summary · View summary" above each compaction's `beforeMessageId`, one per compaction. "View summary" opens the kit Dialog with the sections (a skeleton while it loads). The 0060 fold ("Earlier messages were summarized") is gone: nothing is folded or dimmed.
  - Pages: the page renders the latest 50 messages, at the bottom. Within 400 px of the top, the next older page loads, with a kit Skeleton in its place. The view is put back by hand from the scroll height before and after; the thread has `overflow-anchor: none`, so the browser's own scroll anchoring doesn't apply twice. A first page shorter than the view loads the next one at once, and "Load earlier messages" is there for the keyboard. `?message=<id>` opens the page around that message (scrolled to it and highlighted), and pages load both ways; a link to a message that is gone opens the latest page. Live messages are added only while the latest page is loaded. When the person reads further up (or came from a deep link), "↓ New messages" appears and takes them to the end, loading the latest page if needed. Sending from a deep link loads the latest page first.
  - Route handlers: `GET /api/conversations/:id/messages` and `…/usage` (the query parsed with the API's schema), `POST /api/conversations/:id/compact`, and `GET /api/conversations/:id/compactions/:compactionId`.
- **Tests.**
  - `message-pages.api.test.ts`: the latest page and its cursors; pages newest first with the right first and last edges, a full last page, a one-page Conversation; 57 messages with one `createdAt`; a turn arriving between pages; a deep link paging both ways and cut at an end; 404 for another person and for another Conversation's message; 400 for a foreign or malformed cursor, two directions, or a limit past 100.
  - `context-meter.api.test.ts`: a turn's usage equals `planBudget` for its window (`used`, thresholds, cache reads, the event and the endpoint agree); an 8k model picked gives the 8k plan and a fuller share, a non-model is a 422, another person a 404; `/compact keep the limits` folds before the last turn, passes and stores the focus, sets the divider's message, and "View summary" gives the sections and `current`; a second compaction; an agreed point not in the Spec gives `RECORD_FIRST` with a Spec Proposal card and nothing folded, then compaction after approving; no card for someone who may not propose; 409 with nothing to fold; an automatic compaction recorded as `AUTO` with its event.
  - Updated: the adapters' chat streams end with the usage chunk; a turn's last event is `conversation.usage`.
  - e2e `chat-history.e2e.ts`: a 300-message Conversation opens at the bottom on the latest page; five older pages load with a skeleton, and the message in view moves less than 4 px each time; every message is there once; a reply arriving while scrolled up shows "↓ New messages"; `/compact` then draws a divider with the old messages still shown in full. A deep link loads around a message and pages both ways. The meter's hover, its live update after a turn, `/compact keep …` drawing a divider with the first messages at full opacity, "View summary", and "Compact now" drawing a second divider. The warning colour and label near the threshold. `conversation-compaction.e2e.ts` is rewritten for the divider. All e2e specs pass.
- **Left open.** Automatic compaction doesn't offer the record card before folding (see above). A fold by hand of a very long history on a small summarizer can still fail as in 0060 (a toast; nothing changes). After a turn the meter's `used` is the scaled estimate; the provider's exact count comes with the next load.
