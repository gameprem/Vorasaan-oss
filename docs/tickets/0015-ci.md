# 0015: CI on GitHub Actions

## Goal
Every push and PR runs the same `bun run check` a contributor runs locally, so a red change is caught before merge.

## Scope
- `.github/workflows/ci.yml`: on pull requests and on pushes to `development` and `main`.
- Bun pinned to `packageManager`; `bun install --frozen-lockfile`, so a lockfile out of sync with `package.json` fails.
- A Postgres service with the same image and credentials as `docker-compose.yml`; server tests create and migrate `vorasaan_test` themselves.
- `bun run db:generate`, then `bun run check` (lint → typecheck → test).
- No LLM key in CI: tests use the deterministic fake LLM.

## Acceptance criteria
- [ ] A PR against `development` shows a green `check` job.
- [ ] A lint, type or test failure turns the job red.
